# v1.2.0 GitHub 发布材料

目标仓库：`SevChu/Snooker`。此文件用于发布执行；准备完成不代表已经推送或公开发布。

## 发布元数据

- Git tag：`v1.2.0`，指向包含本次代码、测试、版本及文档的发布提交。
- Release 标题：`Snooker v1.2.0 — 争黑、复位与彩球占点规则完善`
- Release 正文：仓库根目录 `RELEASE_NOTES.md`，与离线 ZIP 内的说明一致。
- 发布类型：正式版本，设为 Latest，不标记为 prerelease。
- README 标题保持 `Snooker`，正文和下载链接使用 v1.2.0。
- About 描述：`Snooker v1.2.0 · 离线斯诺克游戏，支持平分争黑、复位与自由球规则、彩球占点处理及逐局结算。`
- 保留已有仓库名称、主页地址、主题及历史 Release；不移动旧版本标签。

## 发布附件

只上传本次构建的三个文件，避免将目录内旧版附件一并上传：

1. `release/Snooker-v1.2.0.html`
2. `release/Snooker-v1.2.0.zip`
3. `release/SHA256SUMS.txt`

ZIP 内含游戏 HTML、游玩说明、发布说明、LICENSE 与 THIRD_PARTY_NOTICES.txt。校验文件列出本次 HTML 与 ZIP 的实际摘要。二进制附件放在 GitHub Release，源码提交不包含 `release/` 或 `dist/`。

## 发布顺序与验收

1. 确认 `npm test`、`npm run build` 与 `npm run build:standalone` 成功，125 项回归测试全部通过。
2. 检查 package.json、package-lock.json、主页版本号、发布说明、第三方声明和附件文件名一致为 v1.2.0。
3. 推送发布提交到 main，并推送指向该提交的 v1.2.0 标签。先检查远端是否有新提交，避免覆盖他人的工作。
4. 创建使用该标签的 Release，附上正文及三个附件，并设为 Latest。
5. 更新仓库 About 描述，避免 Release 已更新而简介仍停留在旧版本。
6. 核验 tag 对应的提交、Release 的 Latest 状态、三个附件、README 下载地址和 About 文案。下载附件并比对 SHA-256。

发布地址：`https://github.com/SevChu/Snooker/releases/tag/v1.2.0`。准备阶段该地址可能尚不可访问，发布完成后再作为可下载结果交付。
